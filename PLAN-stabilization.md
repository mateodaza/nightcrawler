- **B1** — adds an **explicit prompt-size cap** to the feedback-history change. Last 3 rounds verbatim, older rounds collapsed into a single "prior rounds summary" block generated by a one-shot Sonnet call, total history capped at ~8k tokens. Takes over the guard from `PLAN-context-awareness.md` Phase 3 which the v1 of this plan dropped.
- **B2** — audit feedback is forwarded to the implementer **regardless of plan-audit verdict** (including APPROVED and capped-soft-reject), not only after audit-driven revision. Uses the already-populated `PLAN_LAST_FEEDBACK` at line 1207.
- **Phase A now requires a smoke task** (NC-MEASURE-00) to run end-to-end green before the overnight measurement run. Non-negotiable gate.
- **A5** is behind `NC_MCP_NONBLOCKING=1` until we've verified the 2.1.63 CLI actually honors `MCP_CONNECTION_NONBLOCKING` (confirmation step added).

### Changes since v2 (addressing the second review pass)

- **A3 stderr isolation** — `run_with_timeout.py:54` uses `stderr=subprocess.STDOUT`, so anything Claude CLI or the accumulator writes to stderr lands in the same pipe as the JSON envelope and corrupts it. A3 now specifies an explicit stderr split plus a stdout-heartbeat protocol (see new A3 body). Without this fix, the A3 "zero parser changes" claim is false.
- **A6 plumbing** — now specifies a direct `rc=$?` capture pattern (current `if ! implement_task` swallows 124/125) and a global `LAST_CLAUDE_JSON_PATH` that streamed callees write, so `impl_loop` can read the partial `result` after a kill. Without this, the "tail the partial output into the next iteration" clause in A6 isn't wireable.
- **B2 per-task reset** — `PLAN_LAST_FEEDBACK` is a global that persists across tasks. B2 now explicitly resets it at task-start and at `plan_loop` entry so one task's audit notes can't leak into the next task's first implementation prompt.

### Changes since v3 (addressing the third review pass)

- **A6 — parent-visible envelope path.** v3 tried to set `LAST_CLAUDE_JSON_PATH` from inside `call_claude_streamed`, but the call sites at lines 825 / 1263 / 1323 are `raw_output=$(cd ... && call_claude ...)` — command substitution runs in a subshell, so anything exported inside is invisible to `impl_loop`. Fix: the parent shell computes the envelope path *before* the subshell runs (deterministic from `$SESSION_DIR`, `$task_id`, `$iteration`) and passes it down to the accumulator as a CLI arg (`--envelope-out`). After the subshell returns, the file is on disk at the parent-owned path; `impl_loop` reads it directly. No child→parent propagation required.

## Why this plan exists

The VPS scan (see audit section below) revealed the pipeline isn't "quiet" — it's actively running on camello and bleeding hours + dollars to a small number of fixable root causes. This plan targets only those root causes.

**Observable pain (from recent sessions):**
- `CLAUDE_CLI_TIMEOUT=3600` (1h) exit-124 events: 5–11 per session. Each burns a full hour with empty stdout.
- Per-session cost: $14 (3 tasks) to $112 (7 tasks). Per-task cost: $5–20.
- Review thrash: NC-385 went REJECTED×5 → UNCLEAR×2 → APPROVED → UNCLEAR×4, "DEGRADED APPROVAL." 12 cycles, $26 one task.
- 10-task nights = 8–12h (user-reported).

**Root causes confirmed by reading `scripts/nightcrawler.sh` + session logs:**
1. Implementation runs with **unlimited Claude-CLI turns** (`IMPL_MAX_TURNS=""` default, line 63-64). 100% of `exit 124` events are in impl/revise-impl, never in plan/review.
2. On `exit 124`, feedback to next iteration is the string `"Implementation command failed"` (line 1446, in `impl_loop`) — useless context. Next iteration hangs identically. Death spirals of 5 consecutive 1-hour timeouts observed.
3. `revise_impl` receives only **latest** feedback, not full history (line 1448: `"${feedbacks[-1]}"`). The implementer thrashes because it has no memory of what the reviewer said 3 iterations ago.
4. `MCP_CONNECTION_NONBLOCKING` is not set. MCP bootstrap may be eating part of the turn budget.
5. Runtime config `/home/nightcrawler/nightcrawler/config/models.yaml` is stale vs source. No drift check.
6. 5 git stashes on `main` of `/root/nightcrawler` from stale `timeout`+bash-function iteration (late Feb/early Mar). Fixes they contained either shipped via later commits or are redundant. Noise.
7. `/home/nightcrawler/nightcrawler-old/` dead archive.
8. OpenAI API key in plaintext at `/root/.codex/config.json`.

**What is NOT a cause** (ruled out during research):
- It's not Opus-as-planner: runtime default is Sonnet (`PLAN_MODEL` env var, line 823 `${PLAN_MODEL:-sonnet}`). Opus is only used on escalation (line 1174-1201).
- It's not path duplication: `/root/nightcrawler` is the source checkout, `/home/nightcrawler/nightcrawler` is runtime state via `STATE_DIR` symlink. Split is intentional. Only the config-sync between them is broken.
- It's not the Codex auditor: `/root/.codex/config.toml` correctly says `gpt-5.4`; auditor isn't the slow one.

## Phases

### Phase A — stop the bleeding (Sat, today)

Goal: make the pipeline observable and stop the 1-hour-hang bleed. No logic rewrites, no prompt changes. Additive and flag-guarded. Targets: timeout count 5–11 → 0–1; session hours ~40% reduction.

Every change is in `/root/nightcrawler/scripts/nightcrawler.sh` unless noted. Every change is reversible via env var or `git revert`.

**A1 + A3 are now coupled** — idle-timeout is only meaningful on a stream, and the stream is only safe if we preserve the existing JSON envelope. Do them together, in this order, as a single unit:

**A3. Stream-json wrapper with envelope preservation (do first).**
Add a new callable `call_claude_streamed` alongside `call_claude` (line 144). Do not modify `call_claude` itself — it stays the canonical buffered path for any caller that wants the old behavior.

Contract for `call_claude_streamed`:
```
call_claude_streamed <wall_timeout> <idle_timeout> <prompt> [claude args...]
→ stdout: a single JSON object with the same shape as today's `--output-format json` output
→ exit: 0 on natural completion; 124 on wall timeout; 125 on idle timeout; pass-through otherwise
```

**Stderr isolation is load-bearing.** `scripts/run_with_timeout.py:54` uses `stderr=subprocess.STDOUT`. If we just pipe `claude -p --output-format stream-json ...` through `run_with_timeout.py`, any stderr byte (from the CLI, from MCP-init warnings, from the accumulator itself) will land on the same pipe as the JSON envelope and break the final parse. `stream-json`'s own output is already newline-delimited JSON on stdout, so the fix is to keep stderr out of the timeout wrapper's pipe entirely.

Implementation (three pieces, must all land together):

**(a) `scripts/lib/stream-accumulator.py`** — new file. Reads stream-json events from stdin (one JSON object per line). Maintains running state: partial `result` text, latest `usage` block (`input_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens`, `output_tokens`), latest `modelUsage` block, latest `model`, running `total_cost_usd`.

- All accumulator diagnostics (unknown event types, parse errors, progress notes) go to `stderr` — never stdout.
- Every N stream events (or every 2s wall elapsed, whichever comes first), emit a one-line heartbeat to stdout: `{"_hb": true, "events": N, "bytes": B}\n`. This is what the idle-timer in `run_with_timeout.py` watches — without heartbeats, idle-timeout devolves into a second wall-timeout because stream events alone don't reach the wrapper's stdout pipe until the end.
- On natural stream termination → emit one final stdout line with the JSON envelope: `result`, `usage`, `modelUsage`, `model`, `total_cost_usd`, plus `cost_usd`/`cost` aliases so `log_claude_cli_cost` (line 280) finds any of the three keys it already tries. Also add a sentinel `"_envelope": true`.
- On SIGTERM (parent kills the process group because wall or idle expired) → flush the accumulated state with the same envelope shape plus `"_partial": true` and `"_kill_reason": "wall"|"idle"` (kill-reason derivable from the wrapper's exit code via a side channel — see (c)).

**(b) Consumer-side parse rule.** Callers and the cost logger already read `.result` / `.total_cost_usd` etc. from the *last* stdout chunk (they run `python3 -c "import json, sys; data = json.load(sys.stdin)"`). We change the callers' Python snippets to instead read line-by-line and keep the last line whose parsed object has `"_envelope": true`. Heartbeats are dropped on the floor. This is a 3-line change in each of the two parser sites (lines 270–293 and 843–860) — the fields read are unchanged.

**(c) `call_claude_streamed` shell glue — parent-owned envelope path.** The call sites at lines 825 / 1263 / 1323 use command substitution (`raw_output=$(cd ... && call_claude ...)`), which runs in a subshell — any env set inside is invisible to the parent. So `call_claude_streamed` does **not** try to export `LAST_CLAUDE_JSON_PATH` back up. Instead, the parent shell computes the path *before* the subshell runs (deterministic from parent-visible vars) and passes it down to the accumulator as a CLI arg. After the subshell returns, the file is already at the parent-owned path on disk.

Parent side (e.g. in `impl_loop` or wherever `implement_task` is called from):
```bash
# Compute the path in the PARENT, before any subshell.
LAST_CLAUDE_JSON_PATH="$SESSION_DIR/last_claude.${task_id}.${iteration}.json"
# Persist it so A6 and any other reader can find it after the subshell exits.
# (No child→parent propagation needed — the path is parent-visible by construction.)
```

Inside `plan_task` / `implement_task` / `revise_impl`, we keep the existing command-substitution pattern but pass the path down explicitly:
```bash
local cli_stderr="$SESSION_DIR/cli_stderr.${task_id}.${iteration}.log"
local acc_stderr="$SESSION_DIR/acc_stderr.${task_id}.${iteration}.log"
local envelope_out="$LAST_CLAUDE_JSON_PATH"   # inherited from parent env

set +e
raw_output=$(cd "$project_path" && \
    claude -p --output-format stream-json "${claude_args[@]}" 2>>"$cli_stderr" \
      | python3 scripts/lib/stream-accumulator.py --envelope-out "$envelope_out" 2>>"$acc_stderr")
exit_code=$?
set -e
```

This is wrapped by `run_with_timeout.py` in the outer invocation — `call_claude_streamed` is the function that composes the `sh -c` pipeline and hands it to `run_with_timeout.py` for wall+idle enforcement:
```bash
# call_claude_streamed body (summary)
local wall="$1" idle="$2" envelope_out="$3" prompt="$4"; shift 4
local cli_err="$5" acc_err="$6"; shift 2   # both passed by caller so file lives in parent-chosen session dir

local wrapped=(sh -c '
  claude -p --output-format stream-json "$@" 2>>"'"$cli_err"'" \
    | python3 scripts/lib/stream-accumulator.py --envelope-out "'"$envelope_out"'" 2>>"'"$acc_err"'"
' _ "$@")

python3 scripts/run_with_timeout.py "$wall" "$idle" "${wrapped[@]}"
```

The accumulator writes its final envelope (natural or `_partial`) to `--envelope-out` via an atomic `os.replace(tmp, final)` so partial writes never appear at the path. Stdout from the accumulator still carries the same envelope line for the existing `raw_output=$(...)` parsers.

Because stderr is redirected *inside* the shell pipeline (before `run_with_timeout.py` ever sees the child), the merging in `run_with_timeout.py:54` is now benign — only the accumulator's clean newline-JSON reaches its stdout pipe.

**(d) Partial-state capture for A6.**
- The envelope file at `LAST_CLAUDE_JSON_PATH` is written by the accumulator on every invocation — natural exit and SIGTERM-flush both go through the same `os.replace` atomic write.
- `impl_loop` never exports or re-sets `LAST_CLAUDE_JSON_PATH` from child context. It **owns** the variable, sets it before calling the subshell, and reads the file after. The only failure mode is "accumulator died before writing anything" → the file is absent, A6 handles that case.
- One alternative considered and rejected: returning the path via a dedicated fd (`exec 3>...`) from the child. Works, but adds complexity without benefit over the parent-deterministic-path approach.
- Second alternative considered and rejected: restructuring call sites to drop command substitution (writing `raw_output` to a file instead of `$(...)`). Larger surface change; defer until there's another reason to touch those sites.

This means **zero changes are required** in the parser *field names* at lines 270–293 (cost logger) or 843–860 (plan content extractor) — they keep reading `.result`, `.total_cost_usd`, `.usage`, `.modelUsage`, `.model`. Only the *chunk-selection* logic changes (pick the last `_envelope:true` line). The `_partial` and `_kill_reason` flags are advisory; A6 checks them.

Feature flag: `CLAUDE_CLI_STREAM=0` makes `call_claude_streamed` fall through to `call_claude` (buffered) and skip the idle timeout / `LAST_CLAUDE_JSON_PATH` population. Default on.

- **Reversibility:** `export CLAUDE_CLI_STREAM=0` → every caller runs exactly like today.
- **Risks:**
  - stream-json event schema shifting between CLI versions → accumulator tolerates unknown event types (skip + log to acc_stderr). Smoke task catches schema drift.
  - Heartbeat period misconfigured (too slow → idle-kill fires on healthy runs; too fast → log spam) → default 2s, tunable via `NC_HEARTBEAT_SECS`. Smoke task verifies healthy runs don't idle-kill.
  - Accumulator crash mid-stream → `cli_stderr` log preserves what the CLI was doing; `LAST_CLAUDE_JSON_PATH` may be absent. Caller treats missing file as "no partial available," same as today's failure mode.
- **Expected impact:** post-mortem visibility on hangs; JSON contract preserved; A1 becomes safe to arm; A6 becomes wireable.

**A6. Timeout-aware feedback in `impl_loop` (line 1434-1470).**

Current code at lines 1437-1448 uses `if ! implement_task ...; then ...; fi` — that `if !` inverts the exit status, so `$?` inside the block is always 1 regardless of whether the callee exited 124, 125, or 1. To act on the real code we need the standard `rc=$?` pattern.

**Plumbing (three required changes):**

1. **Capture the real exit code.** Rewrite lines 1437-1448 to:
   ```bash
   if [[ $iteration -eq 1 ]]; then
       LAST_CLAUDE_JSON_PATH="$SESSION_DIR/last_claude.${task_id}.${iteration}.json"
       implement_task "$plan_file" "$PROJECT_PATH" "$task_id"
       local rc=$?
   else
       LAST_CLAUDE_JSON_PATH="$SESSION_DIR/last_claude.${task_id}.${iteration}.json"
       revise_impl "$plan_file" "$(build_feedback_history)" "$iteration"
       local rc=$?
   fi
   ```
   Note `revise_impl` now takes the B1 windowed history, not `${feedbacks[-1]}`. The path assignment happens in the parent shell *before* the callee runs, so it persists after the callee's command substitutions finish.

2. **Pass the path through to the accumulator.** `plan_task` / `implement_task` / `revise_impl` are the sites that actually invoke `call_claude_streamed` (inside their `raw_output=$(...)` subshells). They read `$LAST_CLAUDE_JSON_PATH` from the inherited env and pass it to the accumulator via `--envelope-out` (see A3 part (c)). They do **not** try to export or return it back up. The subshell inherits the env variable; the accumulator writes the envelope file to that path; after the subshell exits, `impl_loop`'s `$LAST_CLAUDE_JSON_PATH` is still its own originally-set value, pointing at a now-existing file (or a missing one if the accumulator never got to write, which A6's `-f` check handles).

3. **Timeout branch in `impl_loop`.** After the `rc` capture:
   ```bash
   if [[ $rc -eq 124 || $rc -eq 125 ]]; then
       local kill_reason; [[ $rc -eq 124 ]] && kill_reason="wall" || kill_reason="idle"
       local wall_sec=$IMPL_WALL_TIMEOUT
       local partial_hint=""
       if [[ -n "${LAST_CLAUDE_JSON_PATH:-}" && -f "$LAST_CLAUDE_JSON_PATH" ]]; then
           # Grab the last ~30 lines of the partial `.result` field for context.
           partial_hint=$(python3 -c '
   import json, sys
   try:
       data = json.load(open(sys.argv[1]))
       res = data.get("result", "")
       lines = res.splitlines()[-30:]
       print("\n".join(lines))
   except Exception:
       pass
   ' "$LAST_CLAUDE_JSON_PATH")
       fi
       feedbacks+=("$(cat <<EOF
   [AUTO] Previous attempt killed after ${wall_sec}s (kill_reason=${kill_reason}).
   Partial output tail (last 30 lines of streamed result):
   ---
   ${partial_hint:-<no partial output captured>}
   ---
   Do NOT retry the same scope. Either:
    (a) split the task into two smaller commits, OR
    (b) output an exit plan listing what was completed and stop.
   EOF
   )")
       timeout_in_a_row=$((timeout_in_a_row + 1))
       if (( timeout_in_a_row >= 2 )); then
           log "Two consecutive timeouts — escalating and breaking impl_loop"
           escalate_urgent "task $task_id" "2× consecutive claude kill (rc=$rc)"
           IMPL_REVIEW_MODE="timeout_escalated"
           return 1
       fi
       continue
   else
       timeout_in_a_row=0
   fi

   if [[ $rc -ne 0 ]]; then
       # non-timeout failure — today's behavior
       log "Implementation failed (rc=$rc)"
       feedbacks+=("Implementation command failed (rc=$rc)")
       continue
   fi
   ```

- **Reversibility:** revert these additions. The `if !` wrapping is equivalent behavior for the non-timeout branch.
- **Expected impact:** no more 5-iteration death spirals; next iteration gets real context (last 30 lines of whatever Claude was doing when killed) instead of today's `"Implementation command failed"` one-liner.

### Phase B — fix the review thrash (Sun–Mon, conditional on Phase A succeeding)

Goal: reduce review iterations per task from 5–12 to 3–5. Ship two of the three shippable-now phases from `PLAN-context-awareness.md` — the ones that don't require infra we don't have yet.

**B1. PLAN-context-awareness Phase 3 — feedback history with size cap.**
`impl_loop` currently passes `${feedbacks[-1]}` to `revise_impl` (line 1448). Change to pass a **windowed + summarized** history to `revise_impl`, not the raw array.

Algorithm (implemented in a new helper `build_feedback_history` called from `impl_loop`):

1. Last 3 rounds: included verbatim.
2. Rounds older than 3: collapsed into a single "prior rounds summary" block generated by a one-shot Sonnet call (`--max-turns 1`, wall timeout 120s) with a prompt like "Summarize these review rounds into ≤200 tokens of still-actionable points. Drop anything the most recent rounds have already addressed." Cache this summary string per-session so we don't regenerate it every iteration.
3. Hard ceiling: if the assembled history (verbatim last-3 + summary) exceeds `NC_FEEDBACK_HISTORY_MAX_TOKENS` (default 8000), progressively drop the oldest verbatim round until under the cap. If still over, truncate the summary. Never drop the **current** round.

Rendering into the `revise_impl` prompt (line 1291-):
```
REVIEWER FEEDBACK HISTORY
(earlier rounds summarized; last 3 rounds verbatim)

--- Prior rounds summary ---
{summary_or_empty}

--- Round N-2 ---
{feedback_n_minus_2}
--- Round N-1 ---
{feedback_n_minus_1}
--- Current round (N) ---
{feedback_latest}
```

- **Reversibility:** `git revert`, or `export NC_FEEDBACK_HISTORY_MAX_TOKENS=0` to fall back to the v1 behavior (latest only).
- **Risk — addressed:** the v1 of this plan dropped this cap; review caught it. Without the cap, long review loops linearly grow prompt size and blow past the cached prefix boundary every iteration, inverting the caching win. The cap is not optional.
- **Risk — remaining:** the summary call itself costs tokens. Cap `--max-turns 1` makes it one round-trip per *new summary event* (summary is memoized until round N+1 pushes the oldest verbatim round out).

**B2. PLAN-context-awareness Phase 2 — audit feedback → implementer, unconditional, per-task-scoped.**

Plan-audit feedback currently only flows into `revise_plan` (line 1167). But most audit findings (file paths, test coverage gaps, naming, missing edge cases) are **implementer-relevant regardless of whether the audit verdict was APPROVED, REJECTED, or CAPPED_SOFT_REJECT**. In `impl_loop`'s first `implement_task` prompt, inject the final plan-audit feedback when available.

Source: `PLAN_LAST_FEEDBACK` is already set at line 1207 (capped-soft-reject branch) and needs to be set consistently on all three verdict branches — approved, rejected-but-accepted, and capped-soft-reject. Specifically:
- Line 1159 (`feedbacks+=("$AUDIT_FEEDBACK")`) — also write to `PLAN_LAST_FEEDBACK="$AUDIT_FEEDBACK"`.
- Line 1167 (after `revise_plan`) — preserve `PLAN_LAST_FEEDBACK` (don't overwrite with empty).
- APPROVED branch (grep for the verdict handling around 1130-1167) — also set `PLAN_LAST_FEEDBACK` from the audit output, because the audit produced feedback even when it approved.

**Per-task reset (required — without this, audit notes leak across tasks).** `PLAN_LAST_FEEDBACK` is a shell global.
